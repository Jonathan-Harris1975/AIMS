AIMS Koyeb build-stage hardening patch - updated files only

Confirmed defects fixed:
- Checked-in AIMS Koyeb env paste files contained literal truncated values ending in `...`.
- scripts/koyebEnvDoctor.js accepted those values, so a broken paste file could still be described as valid.
- npm run build did not validate repo-owned Koyeb env artefacts, so this class of deployment breakage could recur unnoticed.

Files in this patch:
- scripts/koyebEnvDoctor.js
- scripts/buildCheck.js
- koyeb-env/aims.bulk-env.canonical.txt
- koyeb-env/aims.bulk-env.safe-no-google-private-key.txt
- test/koyeb-env-doctor.test.js
- docs/koyeb/STUCK_BUILD_ENV_RUNBOOK.md
- CHANGES.md
- UPDATED_FILES_MANIFEST.txt

Validation completed locally:
- npm ci --ignore-scripts --no-audit --no-fund
- npm run env:doctor:file -- koyeb-env/aims.bulk-env.canonical.txt
- npm run env:doctor:file -- koyeb-env/aims.bulk-env.safe-no-google-private-key.txt
- npm run env:doctor:file -- koyeb-env/rams.bulk-env.canonical.txt
- npm run env:doctor:file -- koyeb-env/blotato-state-corrected.env
- npm run env:doctor:file -- koyeb-env/blotato-state-with-api-key.env
- npm run build
- npm run deploy:smoke
- npm test
- node --check across all JavaScript files

Deployment note:
- Use koyeb-env/aims.bulk-env.safe-no-google-private-key.txt first while Koyeb is stuck in Building.
- Recreate GOOGLE_PRIVATE_KEY as an escaped one-line secret before using the canonical file.
- Any optional value removed from the paste files must be restored only with the complete original string, never a value ending in `...`.
